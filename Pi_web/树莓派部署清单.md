# 树莓派部署清单 — Gemini Pro 相机取流（阶段 4）

> 目标：把 Windows 上已调通的 `camera_capture.py` 原样搬到树莓派运行。
> 原理：脚本是 ctypes 直连动态库，**代码零改动**，只需换 ARM 版库文件。

## 0. 需要拷到树莓派的文件

| 文件 | 来源（Windows 工作区） |
|---|---|
| `camera_capture.py` | 工作区根目录 |
| `OrbbecSDK_linux_arm64.zip` | 工作区根目录（已下载，ARM64 版 SDK v1.10.37，与 Windows 版同版本） |
| `requirements.txt` | 工作区根目录 |

拷贝方式任选：VSCode Remote-SSH 直接拖拽、`scp`、或 U 盘。

## 1. 确认树莓派架构（1 分钟）

```bash
uname -m
```

- 显示 `aarch64` → 用已下载的 arm64 包 ✅（树莓派 4/5 装 64 位系统都是这个）
- 显示 `armv7l` → 32 位系统，需要换 arm32 包（告诉我，我帮你下）

## 2. 树莓派上解压并摆放 SDK（2 分钟）

```bash
cd ~                                    # 或你放项目的目录
unzip OrbbecSDK_linux_arm64.zip
cp -r OrbbecSDK_v1.10.37/SDK ./OrbbecSDK_linux   # 脚本约定加载 OrbbecSDK_linux/lib/libOrbbecSDK.so
```

最终目录结构：

```
项目目录/
├── camera_capture.py
├── OrbbecSDK_linux/
│   └── lib/
│       ├── libOrbbecSDK.so
│       └── （其他依赖 .so）
└── requirements.txt
```

## 3. 装 udev 规则（免 sudo 访问相机）

```bash
cd OrbbecSDK_v1.10.37/Script
chmod +x install_udev_rules.sh
sudo ./install_udev_rules.sh
# 装完后拔插一次相机
```

## 4. 装 Python 环境（5–10 分钟）

```bash
sudo apt update
sudo apt install -y python3-venv libusb-1.0-0
python3 -m venv venv-cam
./venv-cam/bin/pip install -r requirements.txt
```

> 如果 pip 装 opencv-python 太慢/失败，改用系统包：
> `sudo apt install python3-opencv python3-numpy`，建 venv 时加 `--system-site-packages`。

## 5. 验证取流

SSH 远程没有图形界面，用批量模式采集：

```bash
./venv-cam/bin/python camera_capture.py -n 3
```

成功标志：输出 `saved pair 3/3`，`captures/` 里出现 color/depth 图像。
把图像拉回 Windows 查看（VSCode 远程文件面板直接双击就能看）。

# 阶段 5：网页控制台集成（camera_service.py，端口 8009）

> 目标：网页控制台上实时显示相机画面（可见光/深度/红外三路可独立开关），一键保存图像组。
> 新增文件在 pi_web 项目里：`pi/camera_service.py`、`pi/camera.service`，前端 `app/page.tsx` 已带相机卡片。
> 架构：相机服务独立于 8008 控制服务，崩溃/重启互不影响（电机安全优先）。

## 5.1 文件摆放

```
Pi_web/
├── pi/
│   ├── camera_service.py        ← 新增
│   ├── camera.service           ← 新增（systemd 单元模板）
│   └── robot_control_service.py
├── OrbbecSDK_linux/lib/…        ← 阶段 4 摆放的 SDK（camera_service 会向上级目录找它）
├── venv-cam/                    ← 阶段 4 建的虚拟环境
└── pi/captures/                 ← 网页保存的图像组自动放这里（自动创建）
```

SDK 也可以放在 `pi/OrbbecSDK_linux/`（脚本同级），两处都会找；
还可用环境变量 `ORBBEC_SDK_LIB` 显式指定库目录。

## 5.2 装 systemd 自启

```bash
# 按实际路径核对 camera.service 里的 ExecStart
sudo cp pi/camera.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now camera
systemctl status camera        # 应看到 active (running)
journalctl -u camera -f        # 看日志：出现"相机三流已启动"即成功
```

## 5.3 验证

```bash
curl http://127.0.0.1:8009/status
# {"ok": true, "camera": {"connected": true, "fps": {"color": 30.x, ...}}}
curl -X POST http://127.0.0.1:8009/snapshot   # 存一组图到 pi/captures/
```

平板浏览器打开控制台（:5173），相机卡片里点「可见光 / 深度 / 红外」开关看实时画面，
点「保存图像」存一组三张（color_*.png + depth_*.png 16位毫米值 + ir_*.png）。

## 5.4 与阶段 4 工具的关系

`camera_capture.py` 仍是独立的命令行采集工具，但**和相机服务不能同时用**
（同一时刻只有一个进程能占用相机）。要用 camera_capture.py 先 `sudo systemctl stop camera`，
用完再 `sudo systemctl start camera`。

## 5.5 相机服务常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 网页显示"相机服务未连接" | camera.service 没起 | `systemctl status camera` 看原因 |
| 状态里 connected=false 一直重试 | 相机被别的进程占用 | 关掉 Orbbec Viewer / camera_capture.py |
| 画面卡顿/掉帧 | 插了 USB2.0 口 | 换**蓝色 USB 3.0 口**（实测 USB2.0 能跑满 30fps，但余量小） |
| 深度画面全黑、valid 接近 0% | 室外强光压制结构光 | 属预期现象，以可见光为主；红外画面可作参考 |

## 常见问题速查（阶段 4 取流）

| 现象 | 原因 | 解决 |
|---|---|---|
| 报错找不到 `libOrbbecSDK.so` | 目录名不对 | 确认是 `OrbbecSDK_linux/lib/` |
| SDK ERROR / 打不开设备 | udev 规则没生效 | 重做第 3 步并拔插相机；或先 `sudo` 跑一次确认是权限问题 |
| `libusb` 相关报错 | 缺库 | `sudo apt install libusb-1.0-0` |
| 找不到设备 | 线/口问题 | 插树莓派的**蓝色 USB 3.0 口**，用原配线 |
