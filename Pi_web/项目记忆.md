## 一、架构速览（三个服务）

| 服务 | 端口 | 入口 | 职责 |

### 动力硬件（电调与电机，用户确认 2026-10-15）

- **整机重量**：7.45 kg（2026-10-19 用户提供）→ 重力 ≈ 73 N（7.45 kgf），是风机推力计算的基准
- **螺旋桨风机（M1/M3）**：电调 = **AXISFLYING Argus 酷飞 FPV 穿越机电调（BLHeli_32 位，阿格斯 ECO 60A 四合一，4-6S）**；桨 = **6 寸双叶螺旋桨**（用户确认 2026-10-15）；电机为外转子无刷电机，**具体型号（定子尺寸/KV）未记录**——用户口述"电机就是上述"，但已确认型号的是电调，电机疑为酷飞配套，换新时按原规格或拍照确认丝印。树莓派 GPIO18/GPIO19 输出 50Hz PWM 脉宽 1000–1700µs 作为油门信号，**开环控制，无飞控、无 PID**（售后常说的"调 PID"不适用本架构；电调侧可调的是 BLHeli32 的 Timing / Demag / PWM Frequency 等，用 BLHeliSuite32 查看）
- **敲击装置电机**：电调 = **VESC 协议大功率无刷电调**，走 UART `/dev/ttyAMA0` @115200，`COMM_SET_RPM` 指令；电机 7 对极、10:1 减速，输出轴每转敲 1 次
- ⚠️ 两类电调完全不同：风机是穿越机 BLHeli32 四合一（PWM 油门信号），敲击是 VESC（UART 数字协议），讨论/排查时不能混为一谈
- 已评估并否决的替代方案（2026-10-15/16）：① 轮趣 F32C 驱控一体云台电机——云台定位电机，转速/功率/轴结构/串口接口全不匹配，不能带桨；② 大疆 Matrice 4E/4T 桨 1157F/1154F——10.8 寸（27.4×13.7cm）大疆专用快拆接口，装不上穿越机电机 M5 轴，且相对 6 寸桨负载约大一个数量级，强上会烧电机。若目标是降噪，正确路径是选 6 寸低噪桨或换低 KV 大桨盘电机整套重配
- 事故记录（2026-10-14）：M3 风机运行中出烧焦味，拆检发现定子槽黄色绝缘纸烧焦（绕组持续过流所致），M1 正常；旧电机已报废，**已换新电机**。根因未定，怀疑方向：M3 通道信号失步（该路有自转病史）、机械负载异常。新电机首次上电须拆桨低油门（1050–1100µs）短时验证，温度/声音与 M1 对比合格后再带桨渐进加油门

### 相机服务（8009）API
- `GET /status` — 相机在线、四路 fps、D2C 状态与点云内参、已存组数
- `GET /stream?src=color|depth|ir|cloud` — MJPEG 实时流，前端 `<img>` 直显；cloud 为点云透视画面（实时渲染）
- `POST /snapshot` — 保存当前帧；**可选 JSON body `{"srcs": [...]}` 只保存指定画面**（前端按开关状态传入），缺省全存
- `GET /captures` — 已存图像组列表；`GET /captures/<文件名>` — 下载文件（白名单校验）
- `POST /safe-stop` — 安全停止（2026-10-09）：顺带 `sudo -n systemctl stop robot-web` 停掉网页服务，随后本服务 `os._exit(0)` 退出

### 彩色点云（2026-10-09 新增，Windows 实测通过）
- **D2C(HW) 已验证可用**：`pi/d2c_probe.py` 实测 `ob_config_set_align_mode(ALIGN_D2C_HW_MODE)` 被接受，深度帧从 640×400 变为 **640×480 与彩色逐像素对应**；属性 42（DEPTH_ALIGN_HARDWARE）可读可写
- 服务开流时默认开 D2C；老固件若拒绝则自动降级为无色点云，不影响其他流
- 内参开流后经 `ob_pipeline_get_camera_param` 读取（**不要写死**），本机实测 rgbIntrinsic：fx=fy≈453.23, cx≈326.04, cy≈242.82；对齐后点在彩色相机坐标系
- PLY 为二进制 little-endian（xyz float32 + rgb uint8），单次约 7 万点 / 1 MB；已用"投影回 2D 与彩色图对比"验证几何与颜色对齐正确
- **点云是第四路画面**（2026-10-09 下午）：`_render_cloud_view()` 把深度帧降采样（stride 3）反投影后**摇摆模式**（正面 ±0.6 rad 往复，参数 `CLOUD_SWING_RAD`/`CLOUD_SWING_SPEED`，设 0 即固定视角）再透视投影回 640×480，画家算法处理遮挡；**仅在有网页观众时渲染**（cloud_viewers 计数），实测与三流同跑 30fps
- **深度保存附带伪彩图**：保存深度时同时写 `depthvis_*.png`（与网页流画面同一渲染函数 `_depth_vis_bgr`，固定 0.3–5m JET + valid%/中位距离读数），普通看图软件可直接看；原始 `depth_*.png` 仍是 16 位毫米数据
- 前端：开关排四路（可见光/深度/红外/点云），**保存按钮叫「保存图像」，开什么画面就保存什么**（全关则提示不执行）；保存成功 toast 列出实际保存项（含"深度伪彩图"），存了点云则出现 PLY 下载链接；`capture_image` 工具从 localStorage 读最新开关状态同步此行为

### 关键实测结论（2026-10-08，Windows 开发机）
- 三路并发 Color 640×480 MJPG + Depth 640×400 + IR 640×400，USB2.0 下全跑满 30fps
- IR/DEPTH 必须显式 config 开流，格式写设备原生值（Depth=Y11、IR=Y10，SDK 解包为 Y16 交付），写 Y8/Y16 报 "No matched profile found!"
- 设备不支持 frame sync，三路间最大约 33ms 时间差；无 IR_LEFT/IR_RIGHT（单 IR）
- 网页深度图为固定 0.3–5m 量程 JET 伪彩（近亮远暗），左上角叠 valid%/中位距离

## 三、注意事项

- **上传到树莓派**：用根目录 `deploy_to_pi.sh`（2026-10-09 新增，Git Bash 里 `./deploy_to_pi.sh [fangtb02@IP]`）。自动排除 node_modules/缓存/图片，备份旧 camera_service.py，依赖变了才 npm ci，按需重启三个 systemd 服务并健康检查。树莓派上项目目录 `/home/fangtb02/Pi_web`。项目无 git，不要手动散拷文件
- **安全停止（2026-10-09 重做，已实测）**：网页「安全停止」按钮依次停 控制服务(8008) → 相机服务(8009) → 网页(5173)，三个服务真正停住不复活，端口全部释放。关键实现：① 三个 unit 都是 `Restart=on-failure`（崩溃仍会自拉起，干净退出不复活）；② 相机服务退出必须 `os._exit(0)`——正常 return 会让 Orbbec SDK teardown 时 SIGABRT，被 systemd 判失败而重启；③ robot-web 是 vinext dev（workerd 运行时），`/api/shutdown` 的 `process.exit(0)` 是空操作，真正停它的是相机服务 `_quit_soon` 里的 `sudo -n systemctl stop robot-web`。恢复：`sudo systemctl start robot-control camera robot-web`。unit 文件改动后要 `sudo cp pi/*.service /etc/systemd/system/ && sudo systemctl daemon-reload`（部署脚本不做这步）
- **相机独占**：同一时刻只有一个进程能占用相机。`camera_capture.py` 与 `camera.service` 不能同时跑，用前者前先 `sudo systemctl stop camera`，用完 `sudo systemctl start camera`
- **USB**：树莓派上相机插蓝色 USB 3.0 口、用原配线（USB2.0 实测能跑满但余量小）
- **室外强光**：深度可能被阳光压制（阶段 3 未补测），以 RGB 为主、深度为辅；网页深度图左上角的 valid% 是现场判断依据
- **保存的深度 PNG 打开发黑/发白属正常**：`depth_*.png` 是 16 位毫米原始数据（给算法用），普通看图软件按 8 位亮度显示必然异常；随手查看请看同组的 `depthvis_*.png` 伪彩图（2026-10-09 起自动附带）
